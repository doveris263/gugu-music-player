### 已查事实（本轮实测，非推断）

本地起服务（临时数据目录，端口 8899）走完整分片链路，读数如下：

| 用例 | 输入 | 结果 |
|---|---|---|
| 正常上传 | 12MB，切 3 片 | 三片各 132 / 170 / 67 毫秒，全部 200 |
| 收尾 | commit | 28 毫秒返回 200，曲目入库，mime 判成 audio/mpeg |
| 音频分发 | Range 请求 | 206，content-type 正确 |
| 超过上限 | 84MB | 传到 80MB 才返回 413「文件超过 80MB」 |
| 不支持的格式 | `.m4b` | 415 |
| 无分片就收尾 | 不存在的 id | 410 |
| 偏移跳号 | offset 999999 | 409 并回 received |

结论：**服务端分片与收尾逻辑在正常网络下完全正确**，问题不在服务端存储链路。

### 根因分析

「停在 100%」有两处成因，同一批修：

**① 收尾阶段没有任何可见状态，且超时长达 20 分钟**

`public/lib.js` 里每个上传请求设 `xhr.timeout = 240000`（4 分钟）。收尾请求最多重试 4 次，即 4 次尝试 × 4 分钟 = 最坏 16 分钟以上，期间界面只有 `public/app.js` 的「文件名 · 100%」加一个转圈。进度公式 `(body.offset + e.loaded) / total` 在最后一片开始发送时就已到 100%，剩下的等待全在 100% 上度过。反馈者网络卡，正是最容易触发长时间重试的场景。

**② 请求被中止时 Promise 永久悬挂**

`public/lib.js` 的 `post()` 只挂了 `onload`、`onerror`、`ontimeout` 三个回调，**没有 `onabort`**。浏览器中止请求时（面板被关闭、扩展被重新挂载、连接被网络栈重置）这三个都不触发，Promise 永不 settle，`doUpload` 的 `for` 循环卡死在这一首，后续文件也不再处理——界面就永久停在最后那个百分比。

旁证：只要抛出过错误，`public/app.js` 的 `catch` 必调 `report("upload-fail", …)`，而 `server/index.js` 的 `/api/report` 会写一行 `[前端上报] {…}` 进 `server.log`。用户确认「没有报错日志」——说明**根本没有异常被抛出**，是悬挂而不是失败，与②吻合。

### 其它已查实的缺陷

- 分片路由没有结构化留痕。连接断在半路时服务端不记录任何东西；写盘失败与收尾改名失败各有一次 `logError("[upload]", err)`，全服务端只有这两条通用错误转储，都没有房间、文件名、已收字节、耗时。旧的整包上传路由反而写了 `[上传中断]`，分片路由没有。
- 超过上限要传满 80MB 才被拒。反馈者网络卡，这意味着可能先白传 80MB 再看到报错。
- 格式口径三处不一致：选择器 `accept` 少了 aac / opus / webm（用户选不到），界面提示写「mp3 / m4a / ogg / wav」漏了 flac，而服务端白名单是 9 种（mp3 / m4a / aac / ogg / oga / opus / wav / flac / webm）。
- 失败后 `S.uploading` 被重置成「已完成 N 个」，全部失败时显示「已完成 0 个」，语义误导。

### 第 5 轮修订上抛两项的处置

设计席自查出两处并上抛，两项均成立，我已核过代码。需求档已按此改正，设计档还差一处连带。

**处置一：规格 F5 自相矛盾——已改需求档。**

功能点要求复制「以上全部文字」（六项），同一节验收句却只要求「包含文件名与原因」（两项）。这处是我写错的。

改法：验收句改成「剪贴板内容包含卡片上那六项（文件名、大小、阶段、已传百分比、原因、时间）」，与功能点同源。设计档按六项写判据，正确，无需改。

**处置二：收尾「空文件」分支在 HTTP 面不可达——已改需求档，设计需连带。**

核实：`server/index.js` 里 `if (!buf.length) return json(req, res, 400, { error: "空分片" });` 挡在建立上传记录之前，上传记录只在非空分片之后创建；故收尾处 `if (!st.size)` 那条「空文件」在 HTTP 面上走不到。0 字节文件客户端不发分片、直接收尾，此时无记录，走的是 410 过期。

改法（需求档）：
- F6 的收尾失败一项去掉「空文件」，只留写入磁盘失败；验收改为「分片中断与超限两组实跑取读数，写盘失败按代码读数取」。
- F7 把「文件为 0 字节」并入发送前校验，补一条验收：0 字节文件不发出任何分片请求。

需求档该节原文已按此落盘，不再复述。

**设计席需做的唯一连带修订**：删掉为「空文件」新增的日志事件键与它在 §5 触发表里的那一行。理由：需求已不再要求，而给一个走不到的分支加日志，正是「为还没发生过的输入加分支」——它会带来一个事件键、一行判据，却永远没有人走过。分支本身留在代码里不动，不加日志。

其余修订按 §3 逐条已验：规模层级结论表、§9 无验收面点名、accept 由 formats 生成、F6 四字段与样例行、F5 六项、prepare 文字、重试 5 次尝试、formats 前导点、engine.js 复用点、deps 测试缝、§1.4 证据口径、toast 三问、先例两列、分支真实来源（现场报告原话加复现命令形态）、删 localStorage。十五条逐条对得上。

### 主动披露：与设计档不一致的 6 处

1. **`engine.limits` 的读取路径**：设计档 §3 写「`public/app.js` 读 `engine.limits`，不自行再请求第二次」。实现为 `engine` 把 limits 放进既有的 `status` 广播，`app` 读 `S.status.limits`。原因：后台引擎常驻时浮窗内没有 `Engine` 实例，状态广播是浮窗与后台两种运行形态都能到达的唯一通道；「同一接口只在一处发起」这条理由仍然成立。
2. **`xhr.ontimeout` 也标记 `stall: true`**：收尾阶段没有字节推进可言，只能靠超时到点；把「30 秒没回音」与「30 秒没推进」在界面归到同一句「连接停滞，正在重试第 N 次」。看门狗仍是独立的实现，两者口径一致。
3. **失败卡片的位置**：设计档 §8 只写「一张错误卡片……留到用户点 ×」，没指定挂在哪。实现放在 GM 视图顶部（`gmView()` 的返回值里），所有 tab 都能看到、切 tab 不丢。
4. **批量汇总的消失时机**：设计档只写「已完成 N 个，失败 M 个」，没写留多久。实现 6 秒后自动清掉（卡片本身常驻，符合 F5）。
5. **`err` 的 `expired?` 字段未填**：设计档 §2.1 把它列为可选字段，实现里 410 由 `status: 410` + 服务端中文消息表达，没有单独置 `expired`。目前无消费方。
6. **F10 的第二句没有落点**：规格 F10 写「播放出错时只显示一句可读提示，引导刷新页面或联系 GM」，设计档 §8 写「玩家侧无任何改动，仍只有一句可读提示」。实测玩家视图不渲染 `noticeHtml()`（它只在 `gmView()` 的返回值里），`onBus` 的 `error` 分支只走 `toast()`，而 `S.notice` 在玩家视图无处渲染——玩家侧现在没有任何错误提示行，只有「音乐由 GM 统一播放…」这类说明文字。F10 的验收句（无诊断区块、无堆栈与错误码）满足。这一条需要父代理定：给玩家视图补一行中性提示，或把 F10 / 设计档 §8 的措辞改成与现状一致。**本席未擅自新增玩家侧文案**——那是产品口径。

另有两处「设计档未覆盖、本席保留现状并在报告里列明」的观察（代码复核第 3、4 条）：409 续传没有次数上限；200 响应缺 `received` 时把「未确认」当成「已收完」。两者都不会被本仓库服务端触发（它 200 必回 `received`，409 只在 `offset !== st.size` 时出现），改动会新增设计档没有的分支，故留给后续批次裁定。

**为什么加第二条触发源（偏离设计档原文，已获父代理裁定）**

- 该消息只有一个生产者：`public/engine.js` 的 `this.bus.post({ t: "error", error: err.message || "指令失败" });`。
- 它要求令牌：同函数内紧跟着 `if (!this.token) return;`，两个调用点也把门 —— `onEnded` 的 `if (this.role !== "GM" || !this.token) return;`、时长回填的 `this.role === "GM" && this.token && …`。
- 玩家引擎无令牌：role 是 PLAYER，`this.token = lsGet(tokenKey(roomId), "") || ""` 取不到值，永不发这条消息。
- 持牌就变 GM：`becomeOwner()` 里 `this.role = "GM";`，状态广播带 `role: GM`，`public/app.js` 随即把界面切到 `gmView()` 走 toast 那条。
